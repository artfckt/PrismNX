# SwitchColor 0.2 Toolkit Implementation Plan

**Goal:** Expand the existing installed overlay into a useful console toolkit:
18 categorized color presets, real system information, quick controls and links
to installed companion tools. Continue the user's authorized development and
FTP installation workflow; preserve existing Fizeau settings.

**Architecture:** Keep the tested color controller/storage intact. Add a static
preset catalog, an independent optional-service telemetry module and a hub UI.
System pages must work even when Fizeau is absent. Poll only while visible,
about once per second. Missing metrics display unavailable, never fabricated zero.

**Tech Stack:** existing pinned libtesla/Fizeau, libnx 4.12.0, native C++20.

- [x] Implement catalog, category metadata and tests for all 18 unique presets.
- [x] Delegate bounded telemetry/quick-control service module and exact SDK review.
- [x] Split shared UI state/helpers from the color page; introduce a hub, system
  pages, color preset details, quick controls and installed-tool launchers.
- [x] Add diagnostics export on explicit action; preserve configurations.
- [x] Build ARM64, run existing regressions plus catalog/format tests, review.
- [x] Produce 0.2.0 artifacts and prepare verified overlay-only FTP updater.
- [x] Copy 0.2.0 through the authorized FTP endpoint. Completed 2026-09-03:
  528440-byte overlay backed up, uploaded and verified by full readback.
- [x] Document implemented capabilities vs next phases: automatic per-game color
  switching, custom profiles, FPS/frame time integration, history/charts and
  a full-screen companion app. Do not claim those future features are present.

OLED presets are aesthetic LCD color adjustments, not OLED hardware emulation.
No arbitrary clock/charging/fan changes. Quick brightness/volume changes are
explicit actions within supported ranges. Unavailable system control APIs
return a clear error; opening the toolkit never changes system settings.
